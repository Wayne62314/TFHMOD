## 本版优化

- 复用当前场景已经校验的内存区域边界，避免每帧反复执行昂贵的区域查询；场景、角色、对手、管理器、角色资源或回合变化时重新校验。
- 缓存同一角色资源的状态目录；资源或目录边界变化时重新读取。
- 三阶段关闭且恢复控制完成后，移除它的每帧处理；大熊及普通强化开关保留。
- 每帧仍检查当前场景、离线模式、角色身份和存活状态，不缓存书本子对象指针。内存访问异常仍被捕获；缓存不是跨版本或联网安全保证。

模拟测试确认热路径不再重复查询区域，但不能据此声称实际游戏已达到某个帧率。请按下方顺序复测。

## 使用

1. 关闭旧工具并完全退出游戏，将 ZIP 完整解压到新的可写目录，例如 `E:\TFHMOD-UI-241`。不用放进游戏目录，保留 `_internal`，不需要 Python/Node；不要与旧工具同时运行。
2. 游戏正常启动到主菜单，运行新包 `TFHMOD.exe`，确认界面版本 **2.4.2-ui-bilingual1**。
3. 选择需要的开关，点击“连接游戏”。连接前已进场也可以，但必须返回选角重新进场，才能捕获该场战斗的正常初始化。
4. 三个开关：
   - 大熊：P1 选 Arizona → Huggles。
   - 普通强化奥莉：P1 选 Oleander → flag27 强化，普通手控。
   - 三阶段奥莉：P1 选 Oleander → 同时具备 flag27 与三阶段招式控制。普通强化和三阶段同时开启时，以三阶段包含强化的方式工作，不重复创建角色。
5. 三阶段进场后，工具应显示“三阶段已准备”。**游戏窗口前台**按 O 进入飞行，等待约 1.5 秒后 WASD 移动、P 发射追踪弹。Y 恢复手控与进入飞行前的位置，并请求清理弗雷德。再次 O 也可恢复。U 不再触发本工具，保留游戏暂停行为。
6. 保留普通强化开关时，Y 退出飞行后仍是强化奥莉；否则恢复该场进场前原有的 Boss 标志。Y 不重建角色、不回血、不改计时器／胜负。

开关在后续加载时激活；关闭三阶段会尝试在下一次有效游戏更新中退出飞行。建议**先在游戏内按 Y，再断开或关闭工具**。若暂停、切出窗口或进程退出导致清理未确认，窗口会提示；请完全重启游戏，不要继续当前战斗或直接进入联机。

## 模式范围

目标为 **普通自由训练、本地人机、本地双人对战**；只有玩家 1，P2 不修改。沿用大熊工具已调查的离线白名单：fightType=0，或 fightType=10 且 training=1。type1/type11 及其他未调查模式拒绝应用。这里不宣称所有离线街机／锦标赛／剧情模式均受支持。

**禁止联机使用。** 实验后进入联机前，关闭工具并完全重启游戏。模式白名单不是反作弊或联网兼容保证。

## 弗雷德与漩涡

| 按键 | 指令 |
| --- | --- |
| I | 飞行启动完成后召唤 Fred；等待出场，不要连按 |
| J / K | Fred 左 / 右攻击；必须已出现并结束 Start/Intro/当前攻击 |
| Shift + J / K | 强化左 / 右攻击 |
| Ctrl + J / K | 组合左 / 右攻击（原生 Attack_AND 状态） |
| Ctrl + Shift + J / K | 强化组合左 / 右攻击 |
| L | Fred 出场后奥莉开始漩涡；蓄力至少半秒，在蓄力状态下再按 L 请求爆发 |
| Y | 退出飞行、恢复输入并清理自己的 Fred 和其子对象 |

不调用原版无主人过滤的 getFredBoss。工具只在当前活动对象池中沿父链寻找 P1 的 FredBoss；没有或归属不明确就拒绝攻击。

首次召唤时，仿照原生 declareReservedSemiSolidBarriers 的构造和移动流程，向现有碰撞管理器追加 10 个预留半实体位；**不调用 clearBarriers、不加载剧情地图、不替换原地面**。预留位由引擎分配并持有，清理时仅关闭本工具追加且没有活动对象占用的位，本场可复用；不冒险缩减仍可能被引擎引用的数组。没有有效碰撞管理器时拒绝召唤。部分地图或攻击仍可能有未识别的剧情依赖，实际伤害、位置及回合兼容须测试。

漩涡期间仍可操作 Fred；其他角色动作不会强行插入正在进行的召唤。动作长时间不结束会请求清理和恢复。手柄未增加这些快捷键映射；如快捷键与自己的普通攻击键冲突，请调整游戏键位。

WASD 仅用于本实验的低空手动飞行。键盘之外的手柄原有输入保持正常地面玩法，但本版未增加三阶段手柄映射。

## 第一次测试顺序

1. **普通自由训练**：P1 奥莉，三阶段开；重新进场 → O → 等待 → I → 等 Fred 出场 → J/K → Y。先确认无闪退和清理成功，再测试强化、组合攻击和 L → 等待 → L 漩涡。U 应只暂停。
2. 训练重置、返回选角重进，确认没有旧位置或失控遗留。
3. **本地人机**：先测试 O/Y，再测试 P 与 Fred；检查开场、KO、回合切换、再战。
4. **本地双人**：确认 P2 不被修改；注意 P1 的 WASD 快捷键与本地键盘双人自定义键位可能冲突，需自行避开。
5. 关闭三阶段，仅开启普通强化奥莉回归；再选 Arizona 回归大熊。

不建议第一次就同时使用大熊与三阶段，便于定位问题。遇到闪退不要反复连按，记录最后的模式、按键、状态和回合阶段。

## 原理与文件

- `phase3-controller.js`：飞行／追踪弹／弗雷德／漩涡状态机、焦点限制、恢复、对象换代与回合清理。
- `phase3-native.js`：游戏线程适配。通过同构建的 Lua 包装代码定位实际原生函数，使用原 `changeState` 的队列和临时闭包，不直接替换状态指针；位置写入遵循 `setXPos/setYPos`，同步 P1 自己的 Book 子对象。
- `training-hook.js`：保留大熊／flag27 加载逻辑，已识别离线加载完成后为 P1 奥莉准备三阶段。
- `gui.py`：三个独立开关与日志；`launcher.py` 继续校验 EXE SHA256。
- 只读实机检查已确认新增原生函数签名、普通训练的碰撞管理器、召唤和漩涡状态存在。模拟测试不能代替新增招式的实际游戏验证。

本工具仅改进程内存，不安装或更新教程资源，不修改存档。原独立沙盒安装及原 UI ZIP 均保留，不自动覆盖。

日志在 EXE 旁 `logs/ui-hook-进程号.jsonl`。提供模式、开关组合、P1/P2、最后按键、回合阶段和日志即可排查。
