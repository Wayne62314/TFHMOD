# TFHMOD · Huggles 大熊本地可玩工具

在 **Them’s Fightin’ Herds** 的离线模式中，玩家 1 选择 **Arizona**，进入场地后加载 **Huggles（大熊，内部资源名 `bscout`）**。

这是实验性的 Windows 内存工具，不是角色资源替换包，不会修改游戏目录中的文件。选角头像、名称和预览仍是 Arizona；真正替换发生在战斗资源加载前。

## 支持范围与验证状态

| 模式 | 状态 |
| --- | --- |
| 普通自由训练 | 原作者实际测试成功 |
| 本地双人自由对战 | 原作者实际测试成功 |
| 本地人机对战 | 原作者实际测试成功 |
| 在线对战 / 在线房间 | 不支持；代码按对局类型拒绝替换，不要用于在线模式 |
| 故事、街机、回放等其他模式 | 不在支持范围，未验证 |

测试记录来自同一台 Windows 电脑、同一个游戏构建；不代表全平台或所有版本兼容。基础角色加载、操控和招式已由作者验证，全部招式、回合结算、再战、训练录像等功能并未逐项穷尽测试。大熊是隐藏 Boss，可能缺少普通角色的部分功能。

## 环境要求

- Windows 64 位，Steam 版 Them’s Fightin’ Herds。
- Python 3.11 或更高版本，**64 位**。可以从 [Python 官网](https://www.python.org/downloads/windows/)安装；安装后确保 `py -3` 或 `python` 能运行。
- 首次安装需要联网下载固定版本的 [Frida](https://frida.re/) Python 依赖。游戏和工具使用同一普通 Windows 用户运行，不默认要求管理员权限。
- 目前仅支持下方 SHA256 对应的游戏可执行文件。测试时游戏显示 `V6.0.0.WIN`，但相同显示版本不代表二进制一定相同。

```text
Them's Fightin' Herds.exe
SHA256: 03E20EECE23F39FB1012061A5A7FF92F4B63DA23EB8EB641CF6EE379CBCE373D
```

启动器自动从正在运行的游戏读取安装路径，不需要固定盘符、用户名或 Codex。游戏更新后如果校验失败，请等待重新适配，**不要直接删除校验或把哈希替换成新值**：内部函数位置可能已经改变。

## 首次安装

1. 在仓库页面选择 **Code → Download ZIP**，右键下载的 ZIP → **全部解压**；也可 `git clone`。工具应放在独立文件夹，位置说明见下方。
2. 安装上述 64 位 Python。
3. 双击 `Setup.cmd`，等待显示 `Setup complete`。

安装脚本只在此工具目录创建 `.venv`，安装 `requirements.txt` 中固定的 `frida==17.24.3`，不修改系统 Python 环境。不包含游戏资源或第三方依赖二进制。

### 应该解压到哪里？

**不需要放进游戏目录，也不需要放在与游戏相同的盘。** 它是独立运行的小工具，会自动寻找正在运行的游戏；无需向游戏目录、`data01` 或任何 Mod 文件夹复制文件。

例如，你可以先在 D 盘新建 `TFHMOD` 文件夹，把 ZIP 完整解压进去。GitHub 下载的压缩包通常包含一层 `TFHMOD-main`，最终可能是：

```text
D:\TFHMOD\TFHMOD-main\
    README.md
    Setup.cmd
    Start-Huggles.cmd
    runner.py
    training-hook.js
    requirements.txt
    ……其他配套文件
```

这只是示例，不要求你有 D 盘；也可以放在自己“文档”中的独立文件夹。**以能同时看到 `Setup.cmd`、`Start-Huggles.cmd` 和 `runner.py` 的那一层为工具目录**，在里面先运行 `Setup.cmd`，以后从同一位置运行 `Start-Huggles.cmd`。

注意：

- 不要直接在 ZIP 压缩包里双击运行，也不要只拖出两个 `.cmd` 文件；应保留全部配套文件和目录结构。
- 选择普通用户有写入权限、可以长期保留的目录，避免系统目录、`Program Files` 或临时解压目录。安装和运行会在工具目录写入 `.venv` 与 `logs`。
- 安装依赖后不要随意移动整个工具目录，`.venv` 中可能包含原位置记录。如需换位置，在新位置重新解压、重新运行 `Setup.cmd`。

如 Python 未添加到 PATH，可以在工具目录的 PowerShell 中明确指定解释器：

```powershell
.\Setup.ps1 -PythonPath 'D:\Python311\python.exe'
```

## 每次使用

1. 正常从 Steam 启动游戏，等到主菜单，只开一个游戏实例。
2. 双击 `Start-Huggles.cmd`，看到 **`Ready (v2)`** 后保留工具窗口。
3. 进入自由训练、本地双人或本地人机对战。
4. **玩家 1 选择 Arizona**，对手和场地正常选择。进入场地后玩家 1 应为大熊。

如果工具启动时已经在场地内，请返回选角界面，重新选择 Arizona；它不会把已经创建好的小牛原地变成熊。仅替换玩家 1，不替换玩家 2；只选择其他角色时不会触发。大熊固定使用已知可用的调色板 0。

不要同时启动旧测试版和此版本，也不要同时运行多个同类注入工具。公开版本之间会通过进程锁避免重复连接，但无法保证与其他注入器兼容。

## 停用与卸载

- 在工具窗口按 `Ctrl+C` 正常停止；工具会尝试断开 Frida 会话，卸载自己的函数钩子。
- 场上已经加载的大熊不会立即变回 Arizona。**退出并重新启动游戏**，可清除本工具对这次游戏进程的内存改动。
- 工具不会开机自启，也不会在游戏下次启动时自动生效。卸载时关闭游戏和工具，再删除解压目录即可。
- 游戏可能正常保存选角偏好等自身设置；“不修改游戏文件”指工具不改游戏安装资源，并不表示游戏自身不会写存档。

## 工作原理

使用 Frida 连接已有游戏进程，在原生战斗资源加载入口检查对局类型、P1 角色和调用位置，再使用游戏本身的字符串赋值函数，把待加载角色 `cow` 改成 `bscout`。

替换必须同时满足：原生本地对局类型为 `0`、玩家 1 是 `cow`、加载调用来自已验证位置。其他类型全部跳过，不以“非训练”推断“离线”。此外，启动前检查磁盘可执行文件 SHA256，安装钩子前检查关键函数开头字节。不修改 P2、不替换磁盘角色文件、不执行在线房间或管理员命令。

这些检查针对已测试构建，不是对所有未知游戏版本、第三方 Mod 或安全系统的兼容保证。

## 排查问题

| 现象 | 检查方法 |
| --- | --- |
| 提示找不到 Python / 模块 | 安装 64 位 Python，再运行 `Setup.cmd`；仅复制某个启动文件不够，要保留完整目录 |
| 提示没有游戏或有多个实例 | 从 Steam 正常启动，只保留一个游戏，等到主菜单再运行工具 |
| `Unsupported game build` | 游戏二进制不匹配；工具没有安装钩子，不要强行跳过校验 |
| 选角仍是小牛 | 这是预期现象；进入战斗后才替换 |
| 进场仍是小牛 | 确认 `Ready (v2)`、离线模式、P1 选 Arizona，并重新完成选角；检查日志中的 `loading` / `replaced` |
| 提示已有工具运行 | 关闭旧工具；如无法确定，关闭并重启游戏后只启动一次 |
| 注入被拦截或无权限 | 不要关闭安全软件或尝试绕过保护；确认进程与工具权限一致，保留报错后停止使用 |
| 闪退 | 关闭工具重启游戏，先确认不使用工具的普通模式正常，再记录复现步骤 |

运行日志保存在工具目录 `logs/training-hook-<进程号>.jsonl`，不自动上传。提交问题时提供模式、所选双方角色、发生阶段、游戏哈希与相关错误；分享前自行检查日志，不必上传整份游戏日志或崩溃转储。

## 文件说明与开发检查

- `Setup.cmd` / `Setup.ps1`：创建本地依赖环境。
- `Start-Huggles.cmd` / `Start-Huggles.ps1`：定位游戏并检查版本。
- `runner.py`：管理 Frida 会话、进程锁及日志。
- `training-hook.js`：已实测的角色替换逻辑。
- `tests/`：离线模式过滤及钩子行为的模拟测试，不替代游戏内验证。
- `docs/TECHNICAL.md`：当前构建的适配信息和测试边界。

可选：安装 [Node.js](https://nodejs.org/)后执行 `node --test tests/hook.test.cjs`；Windows 下会话模拟测试执行 `.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py"`；语法检查执行 `.venv\Scripts\python.exe -m py_compile runner.py`。

`.cmd` 包装器使用仅对该次 PowerShell 进程生效的执行策略参数，不修改系统持久执行策略。如电脑受组织策略管理，请遵循管理员要求，不要绕过组织限制。
